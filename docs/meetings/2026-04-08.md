### ⚙️ 기술 제안 — 리소스 최적화형 고가용성 응모 시스템 아키텍처 (Kafka-less)
> 제안자: 배강혁

#### 1. 설계 배경 및 목적
- **문제:** 래플(Raffle)/드로우(Draw) 이벤트 시, 전체 응모자 명단을 Redis·DB에 적재할 경우 메모리 및 CPU 부하 급증
- **목표:** Kafka 등 무거운 메시지 큐 없이 Redis와 최적화된 로직만으로 데이터 정합성 및 시스템 안정성 확보

#### 2. 핵심 메커니즘: 시간 슬롯 기반 조기 종료(Early Exit) 전략

| 단계 | 내용 |
|------|------|
| **시간 슬롯 분할** | 당첨 인원 수에 맞춰 응모 시간을 균등 분할 (예: 10명 당첨 → 1시간을 6분 단위로 분할) |
| **슬롯별 난수 타겟팅** | 슬롯 시작 시 당첨 번호 R 생성, Redis `INCR`으로 원자적 순번 부여 |
| **Short-circuit Flag** | `WinnerIsSelected` 플래그를 Redis에 배치하여 당첨자 확정 슬롯의 이후 연산 전면 생략 → 서버 부하 최소화 |

#### 3. 사용자 경험 및 성능 최적화
- **비대칭 응답:** 프론트엔드에서는 모든 사용자에게 "신청 완료, 결과 대기" 메시지 반환
- **결과 조회 분산:** STOMP 기반 Pub/Sub으로 시간차를 두고 결과 알림 전송 → 발표 시점 트래픽 집중 방지

#### 4. 데이터 정합성 및 보안 대책
- **분산 락:** Lettuce / Redisson 기반 락 적용으로 중복 당첨 방지
- **원자적 락 해제:** UUID + Lua Script 조합으로 본인 락만 안전하게 해제
- **영속성 보장 (Write-through):** 당첨 확정 즉시 Redis 캐시 업데이트 + DB 저장 동시 수행
- **인증 보안:** WebSocket/STOMP 연결 시 `ChannelInterceptor`에서 JWT 토큰 검증

#### 5. 기대 효과
- **메모리 효율성:** 전체 응모자 리스트 미보관으로 O(1)에 가까운 메모리 복잡도 유지
- **시스템 가용성:** 당첨자 발생 후 불필요한 연산 제거 → 트래픽 피크 시에도 일정한 응답 속도 보장
- **공정성 확보:** 시간 슬롯 + 완전 난수 방식 결합으로 특정 시점 트래픽 쏠림 및 어뷰징 차단
